# ASIC芯片和TCAM

## ASIC芯片

CPU现所采用的冯·诺依曼架构，当 CPU 处理一个数据包时，需要进行``取指令 (Fetch) -> 译码 (Decode) -> 执行 (Execute) -> 写回 (Write-back)``这一过程。这些设计是为了让CPU具有通用性而设计的。

一个100G的接口，最小包为64B时，理论PPS可达148,809,523 PPS，约等于1.5亿个包/秒。这意味着一个数据包的平均处理时间仅为6~7ns（纳秒），即大约0.006~0.007µs（微秒）。这显然是普通CPU根本无法处理过来的。而数据包的封装、解封装以及数据包的转发等，都是相对固定的过程，不需要那么高的通用性，所以就有了ASIC的设计。ASIC没有复杂的通用指令集。在芯片出厂前工程师便已经把处理数据包的逻辑直接物理固化成了硅片上的逻辑门电路。这使得ASIC只能处理特定的任务，但却能以线速处理数据包。（GPU在某些设计理念上也类似于一类特定领域的ASIC）。

ASIC（Application Specific Integrated Circuit），中文名称为``专用集成电路``。在网络设备中，ASIC主要负责线速转发、MAC学习、隧道封装等。可以说ASIC主要负责的是网络设备的数据平面。这使得CPU只需要负责控制平面即可，例如OSPF、BGP等协议的运行以及设备的管理等。

## TCAM（三态内容可寻址存储器）

TCAM是一种特殊的硬件存储芯片，专门用于高速转发数据包。

### 三态

TCAM 中的 “三态” 指的是每个存储位可以表示三种状态

- 0：表示该位必须匹配0
- 1：表示该位必须匹配1
- X（Don't Care）：表示该位可以匹配0或1，即不关心该位的值。这种状态使得TCAM能够实现带掩码的模糊匹配。

TCAM的每个存储单元使用约10~12个晶体管来实现三态存储，每个bit实际上由两个比较位构成。因此TCAM的成本和功耗都较高。

### 按内容寻址

即提供一个数据内容，存储器在所有条目中并行查找，返回匹配条目的地址。例如，路由表查找192.168.0.0/16的路由条目。

### 优先级与多匹配处理

TCAM支持多条目匹配的情况，通常会为每条目分配一个优先级。当输入数据与多个条目匹配时，TCAM会返回优先级最高的匹配结果。这对于路由表等需要最长前缀匹配的场景非常重要。
