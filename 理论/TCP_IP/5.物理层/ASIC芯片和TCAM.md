# ASIC芯片和TCAM

## ASIC芯片

CPU现所采用的冯·诺依曼架构，当 CPU 处理一个数据包时，需要进行``取指令 (Fetch) -> 译码 (Decode) -> 执行 (Execute) -> 写回 (Write-back)``这一过程。这些设计是为了让CPU具有通用性所设计的。

一个100G的接口，最小包为64B的话，理论PPS可达148,809,523PPS，约等于1.5亿个包/秒。这意味着一个数据包的处理时间为6~7ns≈0.006~0.007ms。这是CPU无法处理得过来的（ 虽然一般也不会上这么`旗舰`的设备），而对数据包的封装与解封装以及数据包的转发等，他是一个相对固定的过程，不需要那么高的通用性，所以就有了ASIC的设计。ASIC没有复杂的通用指令集。在芯片出厂前工程师便已经把处理数据包的逻辑直接物理固化成了硅片上的逻辑门电路。这使得ASIC只能处理特定的任务，但却能以线速处理数据包。（说这货的逻辑为什么这么像介绍GPU？好吧，GPU其实也是一类ASIC）

ASIC（Application Specific Integrated Circuit）,中文名称``专用集成电路``。在网络设备中，ASIC主要负责线速转发，MAC 学习，隧道封装……可以说ASIC主要负责的是网络设备的数据平面。这使得CPU只用负责控制平面即可，例如OSPF,BGP等协议的运行，设备的管理等。
